## Context

当前应用已经存在 `Playlist` 模型、`AppState.playlists` 持久化、侧边栏歌单视图、歌单封面，以及歌曲右键菜单中的“添加到播放列表”。右下角“待播清单”则由 `PlayerStore.manualQueue` 与播放上下文维护，语义是当前播放会话的临时顺序。

本变更的核心不是新增另一套播放队列，而是澄清两类容器的职责：右下角负责“接下来怎么播”，左侧负责“长期如何整理资料库”。因此实现应尽量复用现有 playlist 存储与视图逻辑，只调整用户可见概念和补齐创建能力。

## Goals / Non-Goals

**Goals:**

- 将用户可见的左侧“播放列表”改为“分组”，减少与“待播清单”的概念冲突。
- 在侧边栏分组区提供清晰的 `+` 创建入口。
- 支持创建空分组、持久化分组、进入分组视图、通过歌曲右键菜单添加歌曲到分组。
- 支持分组名称校验、重命名、删除和拖动排序。
- 保持分组与待播清单互不影响：加入分组不改变播放队列，加入待播清单不改变分组。
- 兼容已保存的 `playlists` 数据。

**Non-Goals:**

- 不实现批量分组管理、分组内歌曲排序或分组删除撤销。
- 不实现智能分组、标签系统、多级文件夹或自动规则。
- 不改变 `play-queue` 行为，不改变“下一首播放”“添加到待播清单”“清空待播清单”的语义。
- 不迁移持久化 JSON 字段名；内部仍可使用 `playlists`。

## Decisions

### D1. 保留 `Playlist` / `playlists` 作为底层数据结构

继续使用现有 `Playlist { id, name, songIds }` 和 `PersistedLibrary.playlists`，用户可见文案改为“分组”。这样可以避免已有用户数据迁移，也能复用当前歌单视图、封面马赛克、搜索过滤和持久化路径。

替代方案是把模型重命名为 `MusicGroup` 并把 JSON 字段迁移为 `groups`。这会让代码语义更统一，但需要兼容旧数据、回滚路径和更多重命名工作；对当前窄范围需求收益不够高。

### D2. 创建入口放在侧边栏“分组”标题行右侧

侧栏结构保持：

```text
资料库
  歌曲

分组                         +
  工作背景
  跑步
```

`+` 使用图标按钮，帮助文本为“新建分组”。点击后弹出简洁命名界面；确认时创建空分组并切换到该分组视图。名称校验集中放在 `AppState`，创建和重命名复用同一套规则：裁剪并折叠空白后长度为 1 到 24 个字符，允许字母、数字、空格、中文和少量常用连接符，拒绝控制字符、换行、emoji、纯符号和同名分组。

替代方案是把创建入口放到内容区顶部工具栏。这个位置已经承载搜索、导入、主题和失效曲目清理，且创建分组只服务侧栏分组区，放在分组标题旁更符合作用域。

### D3. 右键菜单使用“添加到分组”

歌曲行右键菜单保留播放相关操作在顶部：

```text
立即播放
下一首播放
添加到待播清单
────────
添加到分组 >
  工作背景
  跑步
────────
在 Finder 中显示
从资料库中删除
```

如果没有任何分组，子菜单可以禁用或提供“新建分组…”入口。为控制范围，首版只要求列出现有分组；无分组时展示禁用项“暂无分组”即可。

### D4. 分组视图沿用现有歌曲表格能力

进入某个分组后，内容区继续使用 `app.viewSongs` 派生歌曲列表，支持搜索、播放、随机播放、当前播放高亮、缺失曲目标识。分组空状态应说明该分组尚无歌曲，并引导用户从歌曲右键菜单添加。

### D5. 分组管理入口放在分组项右键菜单

每个分组行提供右键菜单：

```text
重命名
删除分组
```

重命名复用创建分组的命名 sheet，提交时调用 `AppState.renameGroup`。删除分组使用 SwiftUI 确认弹窗，确认后只删除分组容器和其中的 `songIds` 引用，不删除 `library` 中的歌曲，也不改变 `PlayerStore.manualQueue` 或播放上下文。若当前正在查看被删除的分组，视图切回 `.library`。

拖动排序在侧边栏分组列表内完成，`AppState.moveGroup` 只调整 `playlists` 数组顺序，依靠现有 `didSet` 持久化。

## Risks / Trade-offs

- [内部命名与用户文案不一致] → 在后续实现中把对外文案统一为“分组”，内部变量可逐步重命名但不作为本变更硬性要求。
- [名称校验过严导致部分用户习惯名称不可用] → 允许中文、字母、数字、空格和常用连接符，先阻止明显无意义或可能破坏 UI 的输入；后续可按反馈放宽。
- [创建分组弹窗增加 SwiftUI 状态复杂度] → 将创建状态限制在 `SidebarView` 或小型 sheet 组件中，提交后调用 `AppState` 创建方法，避免业务逻辑散落在视图里。
- [误删分组] → 删除前弹确认；删除不影响资料库歌曲和播放队列，降低破坏性。
- [右键菜单无分组时操作不可用] → 使用禁用文案或后续扩展“新建分组…”入口，避免空菜单误导用户。
- [旧规格仍提到播放列表] → 本变更的 delta specs 应同步更新 `app-shell` 与 `music-library`，归档后主规格应统一到“分组”语义。
