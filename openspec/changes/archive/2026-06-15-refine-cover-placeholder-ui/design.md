## Context

Crate 是 macOS 本地音乐播放器，主要用户是在桌面端管理和播放个人曲库的人。界面的单一职责是让用户快速扫读歌曲、分组和当前播放状态。现有封面占位符来自高饱和 OKLCH 双色渐变，在小尺寸缩略图里容易显脏、显吵，也与本地收藏工具的气质不匹配。

设计方向采用“本地唱片箱”：整体界面保持低噪声、可扫读；缺少封面时显示像唱片纸套和中心标签的默认封面。专辑色相仍用于区分，但只作为边签、中心标签和极淡氛围色出现。

## Goals / Non-Goals

**Goals:**

- 让缺少真实封面的歌曲、专辑和分组封面在表格、队列、播放条中保持统一、耐看。
- 用低饱和色和结构化图形替代明显的整块渐变。
- 收敛播放条氛围色，使当前曲目信息有上下文反馈但不影响控制区可读性。
- 在浅色和深色主题下都保持足够对比度。

**Non-Goals:**

- 不改变导入、元数据解析、封面持久化或播放逻辑。
- 不新增图片资源、字体文件或外部依赖。
- 不重做应用布局、导航模型或表格列结构。

## Decisions

1. 使用 SwiftUI 绘制占位封面，而不是生成静态图片资源。
   - 原因：占位符需要根据专辑稳定色相变化，SwiftUI 图形可直接复用现有 `Album.h1/h2`。
   - 备选：新增资产图片。放弃原因是无法表达专辑差异，且维护浅深色版本成本更高。

2. 将专辑色相从背景主角降级为标签色。
   - 原因：用户明确指出渐变配色难看；结构化纸套 + 唱片标签能保留音乐语义，同时不会在列表里抢注意力。
   - 备选：降低原渐变饱和度。放弃原因是仍然保留“整块渐变封面”的观感，不能解决根本问题。

3. 主题主色从暖橙改为更冷静的针臂青绿色。
   - 原因：现有浅色暖底 + 橙色强调接近常见模板组合；青绿色更像音频设备指示灯，和“本地唱片箱”主题更贴近。
   - 备选：仅修改封面。放弃原因是播放按钮、选中态与新封面标签色会显得割裂。

4. 播放条保留专辑色相反馈，但用低透明度侧向氛围色。
   - 原因：规格已要求播放条基于当前专辑双色相叠加氛围渐变；实现应继续满足该反馈，但降低视觉强度。

## Risks / Trade-offs

- [Risk] 专辑占位图在 34-36pt 小尺寸下细节过多。 → Mitigation：小尺寸主要保留边签、唱片圆形和中心标签，线条宽度按尺寸下限约束。
- [Risk] 改主题强调色会影响用户对按钮状态的熟悉感。 → Mitigation：只调整色相和饱和度，不改变按钮位置、尺寸或交互反馈。
- [Risk] 真实封面与占位封面混排时质感差异明显。 → Mitigation：统一边框、圆角和阴影，让两者在列表中有相同承载容器。
