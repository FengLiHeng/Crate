## ADDED Requirements

### Requirement: 隔离且确定性的截图场景
应用 SHALL 在显式截图启动参数下提供浅色首页、深色首页、浅色待播清单和浅色歌词四个确定性场景。截图场景 MUST 使用固定演示曲库、封面、播放状态、队列和歌词，MUST NOT 读取或写入用户真实曲库、主题偏好或播放记忆。未提供截图参数时，应用 SHALL 保持原有启动行为。

#### Scenario: 启动浅色待播清单场景
- **WHEN** 开发者以 `--screenshot-scene light-queue` 启动应用
- **THEN** 应用使用固定演示内容打开浅色首页并展开待播清单，不修改用户真实数据

#### Scenario: 普通启动应用
- **WHEN** 用户未提供任何截图参数启动应用
- **THEN** 应用按原有逻辑恢复主题、曲库与播放记忆，不加载截图 fixture

### Requirement: 自动捕获 README 截图
仓库 SHALL 提供一个本地脚本，构建最新 app bundle 后逐场景启动应用，等待应用报告窗口就绪，按窗口编号捕获 PNG，并覆盖 `docs/截图/` 中四个固定文件。脚本 SHALL 固定窗口逻辑尺寸，并 SHALL 在失败时终止且保留原错误信息。

#### Scenario: 成功更新截图
- **WHEN** 开发者在有图形桌面会话和屏幕录制权限的 macOS 中运行截图脚本
- **THEN** 脚本生成浅色首页、深色首页、浅色待播清单和浅色歌词四张非空窗口截图

#### Scenario: 截图权限不足
- **WHEN** `screencapture` 因屏幕录制权限不足而无法生成有效图片
- **THEN** 脚本返回失败并提示开发者授予终端屏幕录制权限后重试

### Requirement: README 与输出校验
截图脚本 SHALL 维护 README 中带标记的界面预览区块，并 SHALL 验证四张 PNG 均存在、像素尺寸一致且达到最低可用尺寸。任一校验失败时脚本 MUST 返回非零状态。

#### Scenario: README 截图区块过期
- **WHEN** README 标记区块内容与固定四图布局不一致且开发者运行截图脚本
- **THEN** 脚本将该区块更新为当前四个固定截图引用

#### Scenario: 某张截图缺失
- **WHEN** 截图流程结束后任一固定 PNG 不存在或尺寸不符合要求
- **THEN** 脚本返回失败且不报告更新成功
