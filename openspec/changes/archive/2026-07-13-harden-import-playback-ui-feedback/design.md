## Context

`AppState` 与 `PlayerStore` 是 SwiftUI 共享状态，但当前没有统一的主 actor 隔离；导入和播放引擎构造通过多个 GCD/Detached Task 回传结果。导入缺少阶段状态，重复触发会基于不同快照创建重复专辑；播放引擎加载期间也可再次启动构造。现有歌词页持续自动滚动，空状态和自绘进度滑杆缺少部分直接操作与辅助功能语义。

## Goals / Non-Goals

**Goals:**

- 每次只运行一个可取消的导入任务，并持续反馈已处理数量。
- 在主 actor 应用导入结果时再次按专辑名与艺人合并，保证结果幂等。
- 用明确的播放加载状态和可取消结构化任务代替重复后台构造。
- 明确 UI 共享状态与 AppKit 桥接的主 actor 边界，降低严格并发诊断。
- 改善空状态、进度辅助功能、歌词手动浏览和主要文本缩放体验。

**Non-Goals:**

- 不修改 OTA 更新包签名或信任策略。
- 不改变曲库 JSON、播放记忆或 Release 资源格式。
- 不重做现有主题、表格结构或播放队列语义。

## Decisions

### Decision: 导入由 `AppState` 持有单一结构化任务

`AppState` 维护 `ImportPhase` 和导入 `Task`。导入按钮在忙碌时改为取消入口；后台逐文件解码与元数据读取，每完成一项回到主 actor 更新进度。相比允许多个任务并在最后补救，单任务模型更容易取消，也消除重复点击造成的资源竞争。

即使只允许单任务，应用结果时仍按标准化的“专辑名 + 艺人”查找当前专辑并重映射新歌曲的 `albumId`，防止未来其他入口或状态变化再次产生语义重复。

### Decision: 播放状态显式包含 loading

`PlayerStore` 增加只读加载状态并持有引擎构造任务。开始新播放、停止、删除当前歌曲或清空曲库时取消旧任务；加载期间再次点击播放不会创建第二个引擎。播放条用 `ProgressView` 显示加载反馈，并保持上一首、下一首等既有语义。

### Decision: UI 状态归属主 actor，后台工作只交换可发送值

`AppState`、`PlayerStore`、AppKit delegate/coordinator/cache 标记 `@MainActor`。后台任务只捕获 URL、数值和 `Sendable` 快照；完成后由继承主 actor 的结构化任务应用结果。必须跨 actor 传递的播放引擎采用明确的所有权转移封装，不让后台任务并发访问已经交给主线程的实例。

### Decision: 空状态和辅助功能优先复用系统组件

曲库/搜索空状态使用 `ContentUnavailableView` 并提供导入或清除搜索操作。无歌曲时进度滑杆禁用并从辅助功能树隐藏；有歌曲时读出已播时间和总时长。主要标题、正文和辅助文案逐步使用语义字体，确需自定义尺寸的歌词焦点文本使用 `@ScaledMetric`。

### Decision: 手动浏览歌词暂停自动跟随

歌词滚动容器检测用户滚动，进入暂停跟随状态；当前歌词继续高亮但不抢回滚动位置。界面显示“回到当前歌词”按钮，点击后恢复自动跟随并滚动到当前行。切歌或重新进入歌词页时恢复默认跟随。

## Risks / Trade-offs

- [取消发生在同步解码探测期间不能立即终止底层 AVFoundation 工作] → 每首处理完成后检查取消，不应用已取消任务的结果，并避免启动后续文件。
- [给核心状态增加 `@MainActor` 会暴露既有同步后台调用] → 将纯 I/O/解析函数标为非隔离静态 worker，并通过 `Sendable` 快照交互。
- [语义字体可能改变精细布局] → 只迁移主要可读文本，保留表格列宽和整体视觉令牌，使用截图与最小窗口尺寸验证。
- [歌词滚动检测可能把程序滚动误判为用户滚动] → 用显式的程序滚动标记和短暂复位区分两种来源。
