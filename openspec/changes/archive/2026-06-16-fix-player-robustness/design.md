## Context

Crate 当前是非沙盒 macOS SwiftUI 本地音乐播放器，曲库数据以 JSON 存放在 Application Support，真实音频通过 AVFoundation 播放。近期功能已经覆盖导入、播放队列、失效曲目和封面展示，但审查暴露出几个跨模块问题：播放状态机在不可播边界和异步引擎构造上存在竞态；持久化读写错误被静默吞掉；批量导入仍把较重 IO 放在主 actor；封面原始数据直接进入 JSON，可能拖慢启动、保存和列表滚动。

## Goals / Non-Goals

**Goals:**

- 播放状态机在删除、停止、全量不可播和立即播放插播路径上保持一致，不产生后台音频幽灵播放。
- 曲库读取失败时保护现有文件，写入失败时给用户反馈，不把空曲库自动覆盖到磁盘。
- 导入流程把解码、元数据和封面读取放到后台，主 actor 只提交最终模型变更。
- 持久化封面数据限制为可控尺寸，避免 `library.json` 随原始封面无限膨胀。
- 支持格式文案与实际 `AVAudioPlayer` 校验能力一致。
- 为核心行为补充 SwiftPM 测试入口。

**Non-Goals:**

- 不引入 SwiftData、SQLite 或外部元数据库。
- 不启用 App Sandbox，也不引入 security-scoped bookmark。
- 不改变 `library.json` Codable schema；旧数据仍按现有模型读取。
- 不实现递归目录导入或专辑级高级整理。

## Decisions

1. **播放引擎代次统一废弃**

   `PlayerStore` 保留 `playToken` 作为异步引擎构造代次，但所有会终止当前播放意图的路径都必须递增代次，包括 `stopPlayback()`、删除当前曲目、重置播放会话和开始下一首。相比只在 `startPlaying` 中递增，这能阻止后台构造完成后重新接管已停止的播放状态。

2. **明确插播回归语义**

   `playSongNow` 作为立即插播时不改变上下文位置；该曲结束后 `next()` 应优先消费手动队列，否则继续原上下文当前位置之后的曲目。为避免当前插播结束又重复播放上下文当前位置，`next()` 需要根据 `isManual` 决定是否先递增 `ctx.pos`。

3. **持久化读取失败进入保护模式**

   启动读取 `library.json` 失败时，内存仍以空曲库启动以保证应用可用，但本轮不允许自动写回空快照覆盖原文件。只有用户发生明确曲库变更后才解除保护并写入。写入失败通过 toast 暴露，终止前 flush 继续尝试强制写入。

4. **导入结果后台构建、主线程批量提交**

   导入流程在后台顺序处理文件，生成 `ImportResult`，其中包含歌曲、需要新增或更新的专辑和统计信息。主 actor 一次性合并结果并触发一次持久化。相比并发解析所有文件，这个选择更保守，避免同时打开大量音频文件和图片造成 IO 尖峰；后续如需更快导入可加小并发池。

5. **封面持久化限额**

   导入和启动回填时只保存可解析且不超过阈值的封面数据；超过阈值时尝试按最长边缩放并编码为 JPEG。若压缩失败或仍超限，跳过封面但继续导入歌曲。这样保留当前数据模型，同时控制 JSON 体积。

6. **OGG 从承诺格式中移除**

   当前播放和导入实际以 `AVAudioPlayer` 可解码为准，OGG 并不是 macOS AVFoundation 稳定支持格式。为了避免“支持但总被跳过”的体验，先从扩展名过滤和 UI 文案移除 OGG。

## Risks / Trade-offs

- [Risk] 读取失败保护模式下用户如果继续操作，会用当前空内存曲库覆盖磁盘旧文件。→ Mitigation: 启动 toast 明确提示读取失败；后续可增加“恢复备份/重试读取”入口。
- [Risk] 封面压缩会损失原始封面质量。→ Mitigation: UI 只展示缩略图和播放条封面，压缩后的尺寸足够当前用途；歌曲播放不受影响。
- [Risk] 后台导入仍是顺序处理，超大目录导入速度有限。→ Mitigation: 本次优先修复 UI 卡顿和 IO 峰值；将小并发池留作后续性能优化。
- [Risk] 非沙盒裸路径仍依赖文件原路径可访问。→ Mitigation: 保持既有产品决策，并继续通过失效探测、重新定位和清理能力兜底。
