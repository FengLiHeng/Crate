## Context

歌曲表格由 `NSTableView` 承担大量数据渲染，但当前强制单选，并只把一个 `selectedId` 同步到 `AppState`。曲库顺序同时承担持久化顺序和播放上下文顺序；批量整理需要独立的可见排序、稳定的多选状态，以及不改变底层存储顺序的操作语义。侧边栏已有自定义分组排序拖动，因此歌曲拖放需要使用系统拖放通道并避免干扰该手势。

## Goals / Non-Goals

**Goals:**

- 在不重排持久化曲库的前提下为当前可见歌曲提供稳定排序。
- 让 `NSTableView` 的 Command/Shift 多选成为全局批量操作的唯一选择来源。
- 提供可测试、去重且保持输入顺序的批量收藏、分组和待播行为。
- 使用歌曲 ID 的自定义拖放载荷把所选歌曲添加到普通分组。
- 兼容缺少添加时间字段的历史 JSON。

**Non-Goals:**

- 不支持编辑或重排音频文件本身。
- 不改变搜索结果双击插播或完整视图播放上下文的既有语义。
- 不允许拖放到系统收藏分组，也不实现分组内歌曲手工排序。

## Decisions

1. 在 `Song` 增加可选 `dateAdded`，新导入记录写入导入发生时刻。历史数据解码为 `nil`，排序时将缺失值稳定地置于已有日期之后；不在启动时重写伪造日期。
2. 在 `AppState` 保存排序字段、方向和 `selectedSongIds`。`viewSongs` 在搜索过滤后排序，使用本地化文本比较，最终以原视图位置和歌曲 ID 保证稳定性；`viewPlaybackSongs` 保持原顺序，避免排序或搜索隐式改变正在使用的播放上下文。
3. `NSTableView` 开启多选，选择变化时同步完整 ID 集合。右键未选中行时先把选择收敛到该行；右键已选中行时保留批量选择。双击仍使用点击行作为播放目标。
4. 批量接口统一接收歌曲 ID 集合，并按当前可见顺序解析为歌曲；添加分组和待播均复用或扩展现有单曲业务接口，目标内部去重。删除仅从资料库或当前分组移除，先由视图弹出一次总量明确的确认框。
5. 自定义拖放载荷仅包含当前选择中的歌曲 ID。侧边栏普通分组注册为 drop destination，校验目标不是系统分组，落下后由 `AppState` 批量添加并去重。

## Risks / Trade-offs

- [排序状态不持久化] → 首版将其作为会话级视图偏好，避免扩展持久化格式；每次启动回到标题升序。
- [选择在搜索、切换分组或数据删除后包含不可见 ID] → 每次视图上下文或可见集合变化时求交集，批量操作也再次解析有效歌曲。
- [侧边栏自定义拖动与歌曲拖入竞争] → 分组重排继续使用本地手势，歌曲跨视图拖放使用独立的 `NSItemProvider` 类型。
- [多首歌曲批量加入队列时出现已有条目] → 按输入顺序逐首应用现有队列去重规则，结果确定且不产生重复。
