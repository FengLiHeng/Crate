## Context

应用目前用 `AppTheme` 同时表示用户偏好和实际渲染主题，并在根视图始终设置非空 `preferredColorScheme`，因此无法跟随 macOS。自定义主题令牌仍需要一个明确的浅色或深色值来渲染。

## Goals / Non-Goals

**Goals:**

- 独立表示用户选择的主题模式与当前实际明暗主题。
- 系统模式下让 SwiftUI 跟随 macOS，并让自定义令牌同步使用系统解析后的明暗主题。
- 兼容已有 `light`、`dark` 偏好值和截图模式的固定主题。

**Non-Goals:**

- 不新增第三套视觉令牌。
- 不调整浅色或深色主题的配色。
- 不改变截图场景名称和输出内容。

## Decisions

1. 新增 `ThemeMode` 表示 `system`、`light`、`dark` 用户偏好，保留 `AppTheme` 表示解析后的实际主题。相比让所有视图直接处理可空颜色方案，这能保持现有令牌和视图代码稳定。
2. 根视图仅在固定模式下传入 `preferredColorScheme`；系统模式返回 `nil`。根视图监听环境 `colorScheme`，把系统解析结果同步给 `AppState`，供自定义令牌使用。
3. 继续使用 `lmp-theme` 键持久化模式。已有 `light`、`dark` 原值可直接迁移；没有偏好的用户默认进入 `system`。
4. 主题工具按钮改为菜单，以勾选状态明确展示三个互斥选项。按钮图标反映当前模式，而不是暗示下一次点击的动作。
5. 截图模式把场景主题映射为固定模式，保持确定性并继续禁用真实偏好写入。

## Risks / Trade-offs

- [SwiftUI 环境颜色方案与状态同步存在一个渲染周期] → 初始化时使用 AppKit 当前有效外观解析主题，并在环境变化后立即校正。
- [切到系统模式时系统外观可能与上一次固定主题不同] → 模式切换时先从当前有效外观解析，再由 SwiftUI 环境回调确认。
