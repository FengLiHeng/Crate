## Context

应用当前以 `1240 × 760` 作为首次启动和自动化截图的内容尺寸。该 1.63:1 的比例在固定宽度侧边栏、内容区和播放条共存时偏宽，和界面的音乐播放器气质不够协调。

## Goals / Non-Goals

**Goals:**

- 将首次启动的内容尺寸调整为 `1200 × 800`（3:2），增强窗口的纵向平衡感。
- 让自动化截图使用同一尺寸，以便 README 与应用初始体验一致。

**Non-Goals:**

- 不锁定用户手动调整后的窗口比例或尺寸。
- 不改变侧边栏、播放条和内容区的内部布局或最小尺寸。

## Decisions

- 采用 `1200 × 800` 作为默认内容尺寸。它是更均衡的 3:2 比例，同时宽度仍足以容纳 224pt 侧边栏、歌曲列表与播放控制。相比仅增加高度，适度降低默认宽度可避免大型显示器上出现过多空白。
- `CrateApp` 和 `ScreenshotWindowCoordinator` 共用相同的常量数值。两处都必须更新：前者控制实际首次启动，后者覆盖截图会话的窗口尺寸。

## Risks / Trade-offs

- [用户已持久化旧窗口尺寸而看不到变化] → macOS 会优先恢复用户上次调整的窗口尺寸；该改动仅影响新窗口状态和自动化截图，符合不覆盖用户偏好的预期。
- [较窄窗口压缩表格列] → 新宽度仍显著高于 1000pt 的最小宽度，并保留既有的可调整空间。
