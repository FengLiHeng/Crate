## Context

当前音乐分组由 `Playlist` 模型承载，`AppState.playlists` 负责持久化、排序、重命名、删除和歌曲归类。侧边栏直接遍历 `app.playlists` 展示分组，歌曲右键菜单也直接使用同一列表作为“添加到分组”的目标。

本变更需要新增一个系统默认分组“我的收藏”，并在底部播放条为当前歌曲提供高频收藏入口。该能力跨越数据初始化、分组管理、侧边栏展示和播放条交互，但可以复用现有 `Playlist`、分组视图和持久化结构。

## Goals / Non-Goals

**Goals:**

- 应用启动后始终存在固定 ID 的“我的收藏”分组，并显示在分组列表第一位。
- 用户不能删除、重命名“我的收藏”，也不能通过拖动排序把它移出第一位。
- 底部播放条在有当前歌曲时展示收藏图标，并能一键添加或移出“我的收藏”。
- 分组视图中移除歌曲只修改当前分组，不删除资料库歌曲，也不影响其他分组。
- 收藏状态在本地曲库 JSON 中随分组数据持久化。
- 历史数据无需用户手动迁移；缺失默认分组时自动补齐。

**Non-Goals:**

- 不新增独立收藏数据表或远端同步能力。
- 不改变普通分组的创建、重命名、删除、排序和歌曲右键添加行为。
- 不改变播放队列、播放上下文或音频播放引擎。

## Decisions

1. 使用固定系统分组 ID 表示“我的收藏”。

   在 `AppState` 中定义 `favoritesGroupId` 和 `favoritesGroupName` 常量，例如 ID 使用 `system-favorites`。启动加载持久化数据后调用规范化函数，若缺失该 ID 则插入一个空分组；若存在则强制名称为“我的收藏”并移动到索引 0。

   备选方案是为 `Playlist` 增加 `kind` 或 `isSystem` 字段。该方案语义更显式，但会扩大 Codable 迁移面。当前只有一个系统分组，固定 ID 足以表达约束，且兼容旧 JSON。

2. 所有修改 `playlists` 的路径都通过规范化保护系统分组。

   `deleteGroup` 和 `renameGroup` 对系统分组直接返回并提示或静默拒绝；`moveGroup` 拒绝拖动系统分组，并将普通分组的目标索引限制在 `1...playlists.count - 1`。导入清空、清理失效曲目、删除歌曲等会修改分组内容的路径保留系统分组容器，只调整其 `songIds`。

   为防止旧数据或未来代码路径破坏顺序，可在 `playlists.didSet` 后执行轻量规范化，但需要避免递归触发 `didSet`。实现时可以提供 `normalizeSystemGroups(_:) -> [Playlist]` 纯函数，并在初始化和每个分组写入 API 中使用。

3. 播放条收藏按钮放在播放控制按钮行。

   `PlayBarView.centerControls` 在随机、上一首、播放/暂停、下一首、循环所在按钮行的最右侧加入 `IconButton`，无当前歌曲时禁用。图标默认使用 `heart` / `heart.fill` 或 `star` / `star.fill`，选中态读取 `AppState.isFavorite(_:)`。点击调用 `AppState.toggleFavorite(_:)`，该方法在“我的收藏”分组内追加或移除歌曲 ID，并显示 toast。

   备选方案是放到左侧当前歌曲信息区域。实际界面验证后该位置会破坏歌曲信息与控制区的视觉层级，因此放到播放控制按钮行更一致。

4. 右键“添加到分组”继续包含“我的收藏”。

   “我的收藏”本质上仍是分组，允许用户通过歌曲右键菜单添加到该分组。重复添加仍复用现有去重提示。只有分组管理操作受系统保护。

5. 歌曲右键删除入口按当前视图分支。

   资料库歌曲列表继续显示“从资料库中删除”，调用现有资料库删除逻辑并同步清理所有分组引用。分组视图显示“从此分组移除”，只从当前分组的 `songIds` 中移除歌曲 ID，不调用资料库删除逻辑，不改变其他分组、待播清单或当前播放上下文。

## Risks / Trade-offs

- [Risk] 旧数据里可能已有用户创建的同名“我的收藏”普通分组 → Mitigation: 以固定 ID 识别系统分组；若存在同名普通分组，仍保留用户分组，但系统分组固定在第一位。
- [Risk] `playlists.didSet` 内直接重新赋值会导致递归或额外持久化 → Mitigation: 优先在初始化和公开 mutating API 的赋值前规范化数组，必要时用私有 helper 返回规范化结果。
- [Risk] 播放条空间有限，新增图标可能挤压长歌名 → Mitigation: 图标使用固定尺寸，标题继续 `lineLimit(1)`，当前歌曲信息区域保持弹性宽度。
- [Risk] 收藏按钮与右键添加路径可能产生重复歌曲 ID → Mitigation: `toggleFavorite` 和现有 `addSong` 都检查目标分组内是否已包含歌曲 ID。

## Migration Plan

1. 启动读取 `library.json` 后规范化 `playlists`，自动插入或修正“我的收藏”分组。
2. 持久化仍使用现有 `PersistedLibrary.playlists`，不需要修改 JSON schema。
3. 回滚时如果移除代码，持久化文件中会留下一个普通 `Playlist`，不影响旧版本读取。
