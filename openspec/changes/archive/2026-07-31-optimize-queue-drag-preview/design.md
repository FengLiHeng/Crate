## Context

当前两个待播分区对整行使用 `onDrag`，未提供自定义 preview。AppKit 因此截取包含透明背景的整行视图作为拖动图像；与此同时，`dropEntered` 会实时移动列表中的同一歌曲行。拖动图像和原行内容在目标附近叠加，形成截图中的重复文字、封面与半透明背景。

侧边栏分组使用另一套 `DragGesture`：拖动原行本身并用偏移量推开相邻行。这套实现缺少独立预览与明确槽位，而且与同一侧边栏中的歌曲拖入分组交互共享区域，视觉和行为均与待播排序不一致。

## Goals / Non-Goals

**Goals:**

- 拖动时只出现一个清晰、尺寸稳定的歌曲预览。
- 原列表保留可感知的目标占位，不再显示第二份歌曲内容。
- 待播和普通分组使用一致的预览、占位、实时换位和释放清理语言。
- 浅色、深色与减少动态效果模式下均保持清晰。

**Non-Goals:**

- 不改变队列移动 API、播放记忆或随机模式语义。
- 不改变跨分区拖放限制或无障碍上移/下移动作。
- 不允许拖动系统收藏分组，不改变歌曲拖入普通分组行为。

## Decisions

1. 为两个 `onDrag` 调用提供同一个自定义 `QueueDragPreview`。预览使用固定宽度、单行截断文字、不透明面板背景、边框与轻阴影，避免系统整行透明快照。
2. `QueueRow` 的拖动态把实际内容透明度降为零，并在其上绘制不响应点击的圆角占位轮廓。行本身继续保留布局和 drop hit area，因此实时排序不会产生高度跳变。
3. 把鼠标释放检测提取为两个视图共享的 `MouseDragReleaseMonitor`，使用加入 common run-loop mode 的短周期计时器检查 `NSEvent.pressedMouseButtons`；无论释放点是否为有效目标，只要左键松开就清除拖动态。
4. 侧边栏普通分组使用与歌曲拖入类型分离的系统文本拖动表示、`onDrag` 与 `DropDelegate`，并由当前拖动分组 ID 限定为应用内排序。预览沿用同一实体卡片语言，但缩窄到侧边栏内容宽度；原行使用相同虚线槽位。`dropEntered` 继续调用 `AppState.moveGroup` 实时换位。
5. 分组排序与歌曲拖入由同一个 DropDelegate 按类型分流；系统收藏不注册分组拖动源，也不注册排序目标。普通分组继续使用标准 `Button`，拖动源仅挂在按钮标签内容上，保留键盘与辅助功能语义。
6. 继续以歌曲 ID/分区及分组 ID 作为拖动状态，不改动现有 `PlayerStore` 和分组持久化模型。

## Risks / Trade-offs

- [自定义预览比原行略小] → 固定为面板内可读宽度，并保留封面、标题和艺人以确认拖动对象。
- [完全隐藏原行可能让来源位置不明显] → 使用强调色虚线占位轮廓标示当前插入位置。
- [动画导致占位短暂移动] → 复用现有列表动画和减少动态效果设置，不额外叠加预览动画。
- [拖动结束计时器未清理] → 每次开始新拖动前使旧计时器失效，并在鼠标释放及面板消失时注销。
- [侧边栏两类拖放互相拦截] → 使用不同拖动类型并在单个 DropDelegate 内明确分流，只接受与当前拖动状态匹配的操作。
