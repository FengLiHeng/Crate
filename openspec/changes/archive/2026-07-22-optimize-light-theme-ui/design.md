## Context

Crate 是面向本地音乐收藏者的 macOS SwiftUI 播放器。现有浅色主题以暖米色和酒红为主，但 `winBg`、`sidebarBg`、`panelBg`、`playbarBg` 的明度距离较小；`text3` 还承担小字号栏目标签，非当前歌词又在次级文字上叠加透明度。结果是浅色界面的结构、可读性和状态语义弱于深色主题。

本次设计以“唱片收藏册 / liner notes”为主题：主内容是纸面，侧栏和播放栏是固定装订轨道，待播清单与菜单是抬升纸页。专辑封面继续作为主要色彩来源，酒红只用于播放和关键状态。

## Goals / Non-Goals

**Goals:**

- 拉开浅色主题主内容、固定轨道和抬升浮层的明度层级。
- 让小字号标签和非当前歌词在浅色模式下保持清晰可读。
- 通过唱片索引脊线形成 Crate 的侧栏辨识度。
- 区分普通选择、当前导航与正在播放状态。
- 降低头部低频和破坏性操作的常驻视觉重量。

**Non-Goals:**

- 不改变深色主题的石墨与薄荷绿方向。
- 不引入自定义字体、毛玻璃系统或新的图像资源。
- 不改变播放、导入、曲库、队列和歌词解析逻辑。
- 不用专辑封面颜色动态替换全局主题强调色。

## Decisions

### D1：建立六个核心浅色视觉角色

- 主内容纸面：`#F8F6F1`
- 侧栏与播放轨：`#EEE8DE`
- 抬升浮层：`#FFFDF9`
- 主墨色：`#282421`
- 可读次级文字：`#6E675F`
- 品牌酒红：`#A3344D`

现有 SwiftUI 令牌结构保持不变，并从这些核心角色派生 `text2`、分隔线、hover、中性 selected、控件底色和强调柔色。选择这一方案是为了保留暖白气质，同时让层级来自稳定明度关系，而不是增加阴影或毛玻璃。

替代方案是改为纯白与系统灰，优点是更接近原生工具应用，但会失去唱片收藏册辨识度，因此不采用。

### D2：普通选择与播放强调分离

歌曲行普通选中背景改为低透明度暖灰；当前播放继续使用酒红标题和均衡器。侧栏当前导航使用低透明度酒红底，并增加 3px 酒红索引脊线。这样酒红仍表达当前状态，但不会让所有选择都产生同等强度。

替代方案是继续复用同一 `selected` 令牌，代码更少，但无法区分“用户刚选中”和“播放器正在播放”，因此不采用。

### D3：通过颜色而非透明度控制歌词层级

非当前歌词使用可读的专用次级颜色和中等字重，不再在文字颜色上叠加约半透明度。当前歌词继续通过字号、粗体、墨色和酒红脊线获得焦点。大尺寸封面外增加细窄纸框，保留直角封套观感。

替代方案是仅提高现有透明度，但透明颜色与不同背景叠加后对比度仍不稳定，因此不采用。

### D4：头部工具栏按频率分层

搜索框保持常驻底色；导入按钮使用轻酒红底作为主要工具动作；主题和普通图标按钮仅在 hover 时出现背景；清空资料库移入更多菜单，确认流程保持不变。失效曲目清理仅在需要时继续显示。

替代方案是让所有按钮保持同样的实心底色，但会继续造成视觉权重平均化，因此不采用。

### D5：浮层以更亮表面表达抬升

浅色待播清单和菜单使用比主纸面更亮的背景，并配合细分隔线和克制阴影。播放栏与歌词页的专辑氛围色降低到轻微范围，只用于连接封面与当前播放内容。

## Risks / Trade-offs

- [侧栏索引脊线可能与窄窗口边缘显得拥挤] → 保持导航项现有高度，并将脊线放在行内而不是额外占宽。
- [更深的次级文字会减弱当前歌词焦点] → 使用字重、字号、当前墨色和酒红脊线共同建立焦点，不依赖降低正文可读性。
- [透明派生色在不同表面上观感略有差异] → 只对 hover、selected 和 accentSoft 使用透明色；正文与核心表面使用不透明颜色。
- [工具栏更多菜单降低清空入口可见性] → 清空属于低频破坏性操作，保留明确菜单文案和二次确认。
